# Rollfast 1.1.0

Rollfast 1.1.0 reduces repeated optimizer work and simplifies shared internals.
The release preserves the v1 public API, optimizer defaults, state layouts,
checkpoint formats, and stochastic-rounding key sequences.

## Performance

### Scheduled and rejected updates

GaLore now computes SVD bases and transports projected moments only on refresh
steps. APOLLO generates random projections only when its refresh interval is
reached. EMA/SWA casting and averaging and AdaLoRA rank allocation also run
only at their existing update boundaries.

Loss-scaled and stateful SAM steps bypass pure optimizer computations when
nonfinite values reject the update. Transformations with collectives or custom
effects retain their original execution so replica participation and callbacks
remain consistent.

### Matrix solvers and microbatches

Aurora skips conjugate-gradient matrix products after the solver has converged,
while retaining reverse-mode differentiation. PSGD reuses the preconditioner
already selected by its update conditional.

SAM and `LossBundle` microbatch accumulation use sequential JAX scans. This
keeps the traced body size independent of the microbatch count, while preserving
the sum order, reduction policy, auxiliary totals, and final model-state output.

### State initialization and transfers

Adam8 caches its immutable host codebooks and zero codes, initializes quantized
zero moments directly, and avoids child-key splits that deterministic storage
does not use. Quantized values, scales, metadata, and parent-key progression
remain compatible with existing state.

Factorized AdamW evaluates learning-rate schedules once per parameter group.
Optimizer-state offload batches eligible leaves into one host-transfer request.

These improvements remove unnecessary work in specific paths. End-to-end gains
depend on the optimizer, refresh cadence, microbatch count, and hardware.

## Maintenance and tests

Shared helpers consolidate moment updates, matrix routing, schedule construction,
fine-tuning compiler assembly, state traversal, and update application. Public
Optax symbols replace equivalent private imports where available.

The test suite shares repeated fixtures and cases, uses numerical references
for selected distributed and fallback paths, and stores readable public export
snapshots. New performance regressions cover work avoidance, dtype and state
compatibility, PRNG sequencing, differentiation, and physical CPU-device sharding.
The [production audit](../dev/finetuning_audit.md) and
[test audit](../dev/testing_audit.md) record the earlier simplification work.

## Compatibility

No migration is required when upgrading from 1.0.0. Python 3.12+, JAX 0.6.2+,
and Optax `>=0.2.8,<0.3.0` remain the supported dependency requirements.
Equinox and Equimo integrations remain optional. The
[v1 stability policy](../stability.md) continues to apply.

## Validation scope

Validation covers the full test suite, minimum supported JAX/Optax versions,
four forced CPU devices, lint, formatting, typing, CI examples and benchmark
smoke scripts, distribution metadata, and installation from the built wheel.
The [release checklist](../release-checklist.md) defines the publication gates.

GPU execution and accelerator throughput have not been verified. The CPU checks
and focused timings do not establish performance on production training workloads.

## Known limitations

The existing optimizer-profile caveats remain documented in optimizer reports.
The production audit also records two existing fine-tuning limitations:

- With gradient accumulation and EMA/SWA enabled, rejected accumulated updates
  can advance averaging counts and include a duplicate iterate.
- Schedule-Free plan updates using typed `jax.random.key(...)` keys fail in
  the finite guard; legacy `jax.random.PRNGKey(...)` keys remain supported.
