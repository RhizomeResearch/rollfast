# Rollfast 1.5.0

Rollfast 1.5.0 removes the branch around the optimizer when rejecting nonfinite updates, which cost about 390 ms per
update on H100 GPUs. It also makes Kron and Riemannian Aurora faster to update and compile, keeps the plan's no-decay
groups undecayed, and lets `ScheduleConfig` select WSD warmup and decay shapes. Optimizer defaults, state structure, and
checkpoint format versions are unchanged.

## Branch-free nonfinite rejection

The nonfinite guard and the fine-tuning update commit no longer branch around the optimizer. A rejected update now runs
one optimizer pass on zero gradients and discards its result, so the moments, counts, and parameters stay where they
were. On H100 GPUs this removes about 390 ms per update, and with donated buffers it avoids copying parameters and
optimizer state.

`scale_by_adam`, `galore_adamw`, `apollo_adamw`, and `apply_hyperball` no longer read parameters when the weight decay
is a static zero, which saves one multiply and add over all parameters per update for default AdamW.

## Kron and Riemannian Aurora

Kron no longer branches around its lazy scale initialization and factor balancing. For 30 256x128 matrices on an H100
GPU, one update went from about 800 ms to 5 ms. The preconditioner update itself remains conditional. Kron also shares
its per-factor key splits and norm-estimator noise across leaves, so XLA compile time follows the number of distinct
factor shapes rather than the number of leaves. The drawn values are unchanged.

Riemannian Aurora keeps its loops rolled. For 8 256x128 matrices on an H100 GPU, one update went from about 48 s to 26
ms, and compile time went from 90 s to 2.5 s.

## Weight decay follows the plan

`GroupRule` weight-decay overrides no longer enable decay on groups the plan marks as no-decay. A broad rule such as
`GroupRule(role="backbone", weight_decay_value=0.05)` previously also decayed the backbone's biases, norms, and position
embeddings. Rules still change the coefficient of groups the plan decays.

`DEFAULT_NO_DECAY_TAGS` also lists `block.layer_scale`, `ssm`, and `vector` (arrays with at most one axis), matching
Equimo 2.8's default no-decay policy. `galore_adamw` and `apollo_adamw` accept `weight_decay_mask`, a boolean tree or a
callable returning one, like the other AdamW variants.

## WSD shapes

`ScheduleConfig(kind="wsd")` accepts `warmup_shape` and `decay_shape` (`linear`, `cosine`, `power`, or `exponential`),
with `warmup_power`, `decay_power`, and `exponential_rate`, and builds the same schedule as `wsd_schedule`. They default
to linear and are ignored by other kinds. See [fine-tuning configuration](../finetuning/configuration.md) for the WSD
slot counts.

## Compatibility

Rollfast's base requirements are unchanged: Python 3.12+, JAX 0.6.2+, and Optax `>=0.2.8,<0.3.0`. The checkpoint schema
and array format remain at version 1.

Review these behavior changes when upgrading:

- A `GroupRule` decay override that matched no-decay groups no longer decays them, so training results change for such
  rules.
- Recipes built on `DEFAULT_NO_DECAY_TAGS` stop decaying layer scales, SSM parameters, and vectors.
- Checkpoint manifests record the WSD shape fields. Manifests written by 1.4.0 restore under strict validation as linear
  WSD schedules; 1.4.0 cannot restore manifests written by 1.5.0.

## Known limitations

- A rejected update still costs one optimizer pass.
- The limitations listed in the [1.4.0 notes](1.4.0.md#known-limitations) remain.
