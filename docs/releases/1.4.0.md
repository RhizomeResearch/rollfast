# Rollfast 1.4.0

Rollfast 1.4.0 makes supplied master parameters follow the precision policy, and names the Adam hyperparameters in the
AdamW builder signatures. Optimizer defaults, state structure, and checkpoint format versions are unchanged.

## Master parameters follow the precision policy

`FineTuneStepState.master_params` is `None` when the precision policy keeps no masters, but 1.3.0 did not enforce this
for masters supplied by the caller. `init_finetune_step_state` stored them under any policy, and the master-aware steps
then optimized them. Under `PrecisionConfig(master_params="never")`, a BF16 run trained float32 masters while
`report.precision` said `master_free_nearest`, and its step-state checkpoint stored them. Float32 weights under
`master_params="auto"` gained a second float32 copy, and `bf16_master_free_precision()` failed only at the first step.

`init_finetune_step_state` and the steps that take masters as an argument now raise `ValueError` when the policy keeps
none. Pass masters only when the bundle reports them:

```python
masters = fp32_plan.trainable if optim.report.precision.master_params else None
state = rfft.init_finetune_step_state(
    optim, plan.trainable, master_params=masters, rng_seed=0
)
```

[Low-precision fine-tuning](../finetuning/precision.md#steps-that-honor-the-policy) now shows where both partitions come
from. Partition the float32 model and its BF16 copy, compile the bundle on the BF16 plan so that `master_params="auto"`
resolves against BF16 dtypes, and pass the float32 partition as the masters. Masters derived from the BF16 copy keep its
rounding, which loses nothing only when the published weights are BF16.

## AdamW builder arguments

`adamw_from_plan`, `adamw8_from_plan`, and `galore_adamw_from_plan` name `b1`, `b2`, and `eps` in their signatures, so
the values show up in type checking and editor help instead of passing only through `**kwargs`. The defaults are
unchanged: `b1=0.9`, `b2=0.999`, and `eps=1e-6`. Optax, PyTorch, `schedule_free_adam_from_plan`, and the Adam groups of
the hybrid builders default to `eps=1e-8`; pass `eps=1e-8` to match them. APOLLO keeps `eps` on `APOLLOConfig`. The
resolved values remain in `bundle.optimizer_config` and `bundle.manifest()["optimizer"]`.

## Compatibility

Rollfast's base requirements are unchanged: Python 3.12+, JAX 0.6.2+, and Optax `>=0.2.8,<0.3.0`. The checkpoint schema
and array format remain at version 1.

Review these behavior changes when upgrading:

- Code that passes `master_params` under a policy that keeps none now raises `ValueError`, at `init_finetune_step_state`
  or on the first call of a step that takes masters as an argument. Under stochastic parameter rounding, the error now
  comes from `init_finetune_step_state`, with a new message.
- A step state or step-state checkpoint from 1.3.0 that holds masters under such a policy still restores, but its first
  step raises. To continue under the declared policy, drop the masters with
  `dataclasses.replace(state, master_params=None)`.

## Known limitations

- Without supplied masters, `init_finetune_step_state` derives them from the trainable leaves. It cannot tell whether
  BF16 or FP16 values were rounded from float32 weights.
- `hybrid_kron_adam_from_plan` fixes the `eps` of its Adam groups at `1e-8`.
- The limitations listed in the [1.3.0 notes](1.3.0.md#known-limitations) remain.
