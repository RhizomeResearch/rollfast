# Rollfast 1.2.0

Rollfast 1.2.0 adds safer fine-tuning checkpoints and clearer update and evaluation state. It also qualifies grouped
optimizer plans and stateful updates with Equimo 2.4.0. The public v1 optimizer interface and existing checkpoint format
versions remain in place.

## Fine-tuning checkpoints

`save_array_state_checkpoint` and `load_array_state_checkpoint` provide bounded, non-executable optimizer-state storage
with checksums and array-layout validation. A distributed save writes each process's local shards to a shared POSIX
filesystem and publishes the completed generation atomically. Restore requires explicit limits and a trusted template
from the same compiled plan; the original process count and equivalent sharding must be available. The model artifact
remains separate and is bound by its checkpoint identity. See
[state and checkpoints](../finetuning/state_and_checkpoints.md) for the save and restore contract and
[the runnable example](../../examples/finetuning/array_checkpoint.py).

Logical checkpoint restore now validates the effective group table and available state-schema description alongside the
plan fingerprint and model identity. Callers may also require a matching base-model hash and applied-update count.
Component-presence metadata is checked against the stored state. Older schema-version-1 checkpoints without a
state-schema description can be restored with a matching template. Trusted-local pickle loading still requires
`trusted=True`.

## Updates and evaluation

`OptimizerBundle.update_with_status` distinguishes accumulating microsteps, applied updates, and discarded windows.
`validate_accumulation_complete` catches an unfinished accumulation window before a host-side lifecycle boundary.
Rejected windows do not advance the guarded optimizer's applied-update count. Stateful loss and SAM steps retain the
incoming model state when an update is rejected; loss-scaled steps also reject gradients that become nonfinite in the
configured gradient dtype.

`bind_evaluation_view` constructs an `optimizer` or enabled `ema`/`swa` view from matching model and optimizer
checkpoints. It checks the model identity and update position and includes the matching model-state snapshot in the
returned view. See [averaging](../finetuning/averaging.md) for usage.

Required group selectors now fail when they match no trainable group. The grouping report exposes each selected
parameter's logical identity, physical path, and effective rate. Query-model guidance covers encoder and head groups,
loss denominators, annealing position, normalization validity, and checkpoint replay without coupling the optimizer to
one model library; see [query models](../finetuning/query_models.md).

## Compatibility

Rollfast's base requirements remain Python 3.12+, JAX 0.6.2+, and Optax `>=0.2.8,<0.3.0`. Equimo and Equinox remain
optional to the base import. The development integration now requires Equimo `>=2.4.0,<3.0.0`; the released 2.4.0 wheel
matched the upstream source used for query-model qualification. The declared interval is an API range. Record exact
dependency versions for a training run and consult [fine-tuning compatibility](../finetuning/compatibility.md) when
restoring older checkpoints.

No migration is required for the public optimizer API. Checkpoint users should rebuild a matching restore template,
retain the corresponding model artifact, and record applied updates and random streams. The new array format is an
additional storage option; it does not convert application-owned legacy checkpoints.

## Known limitations

The existing averaging and Schedule-Free limitations remain:

- When accumulation and EMA/SWA are combined, a rejected completed window can advance averaging counts and include a
  duplicate iterate, even though the guarded optimizer does not apply a parameter update.
- Schedule-Free plan updates using typed `jax.random.key(...)` keys fail in the finite guard; legacy
  `jax.random.PRNGKey(...)` keys remain supported. The typed-key checkpoint fix does not change this update path.

## Validation scope

On Python 3.12, the current stack passed 814 tests with 13 skipped; the minimum JAX 0.6.2 / Optax 0.2.8 stack passed 792
with 13 skipped. Four-device CPU checks passed 13 tests. The six example and benchmark smoke commands, Ruff, mdformat,
Ty, version consistency, and a fresh import from the built wheel also passed. The separate Equimo 2.4.0 qualification
covers real query-model losses and checkpoint replay. Accelerator and pretrained model parity require their own checks;
these CPU results do not establish those profiles. See the [release checklist](../release-checklist.md) for publication
gates.
