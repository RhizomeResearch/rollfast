# Rollfast 1.6.0

Rollfast 1.6.0 removes the conditionals that stalled optimizer and fine-tuning updates on H100 GPUs with NVIDIA driver
595, and lets `ScheduleConfig` index the learning-rate schedule by update attempts. Optimizer defaults, state structure,
and checkpoint format versions are unchanged.

## Updates no longer stall on H100 GPUs

XLA captures a `lax.cond` into a CUDA graph by default. On H100 GPUs with driver 595.91, each execution of such a
conditional cost about 390 ms, whether its branch ran or not. Update paths no longer contain one: cheap branches are
computed and selected, and expensive, usually skipped work (Kron's preconditioner update, GaLore and APOLLO refreshes,
Pion's alternating sides) runs in a zero-or-one-trip loop shared by all leaves.

On an H100 with eight 2048x2048 layers, one step went from about:

| Path                          | Before | After   |
| ----------------------------- | ------ | ------- |
| Hybrid Kron fine-tuning       | 400 ms | 14 ms   |
| APOLLO                        | 389 ms | 1.5 ms  |
| EMA and SWA                   | 156 ms | 1.6 ms  |
| Accumulating loss-bundle step | 148 ms | 1.1 ms  |
| Pion                          | 116 ms | 15 ms   |
| AdaLoRA controller            | 367 ms | 0.05 ms |

Other GPUs did not stall. There the skip loops add about 0.1 to 0.2 ms per step, and EMA and SWA updates are about 23%
faster.

## Attempt-indexed schedules

`ScheduleConfig(step_counter="attempt")` advances the schedule on every update attempt: an applied update, a rejected
nonfinite update, a discarded accumulation window, or a skipped batch. Adam moments, bias correction, and weight decay
still follow applied updates only. Fits that see empty batches at different attempts therefore share one learning rate
per attempt. With accumulation, one attempt is one optimizer window.

The attempt clock is the optimizer state's existing schedule count, so it needs no new state and is saved and restored
with the optimizer state. `apollo_adamw_from_plan`, `galore_adamw_from_plan`, and `schedule_free_adam_from_plan` read
the learning rate from a count that other state shares, so they accept only `"optimizer"`.

`make_skip_attempt_step(bundle)` records a batch without training targets as a skipped attempt. It computes no loss or
gradient and leaves parameters, optimizer moments, model state, loss scale, and RNG streams unchanged; under `"attempt"`
it consumes its schedule slot. See
[schedule clocks and skipped attempts](../finetuning/configuration.md#schedule-clocks-and-skipped-attempts).

## Collective nonfinite windows

`make_accumulating_loss_bundle_update_step` with a declared collective axis skips a window on every partition when any
partition saw a nonfinite microbatch. Previously only that partition skipped, leaving the others in the optimizer's
collectives.

## Compatibility

Rollfast's base requirements are unchanged: Python 3.12+, JAX 0.6.2+, and Optax `>=0.2.8,<0.3.0`. The checkpoint schema
and array format remain at version 1, and the default `step_counter="optimizer"` behaves as before.

## Known limitations

- The skip step requires `AccumulationConfig(steps=1)`.
- `ScheduleConfig(step_counter="micro")` remains unsupported.
- The stall depends on the GPU and driver: H100 with driver 580.173, B200, RTX PRO 6000, A100, RTX 4080, and CPU did not
  stall. Check performance claims about branches on the affected setup.
- The limitations listed in the [1.5.0 notes](1.5.0.md#known-limitations) remain.
